# 调用当前读屏解释词库的可行性调研

日期：2026-11-16。范围：仅调研，不修改模块词库、候选朗读或手机读屏设置。

## 结论

“由当前读屏朗读它自己的解释”有条件可行；“模块直接取得当前读屏的解释文本”没有发现 Android 通用公开接口。对当前手机的解说，找到了插件桥接的内部调用线索，但尚未运行验证，不能写成已支持。

建议先验证解说原生解释路径：模块发送原始单字，由解说根据自己的解释设置处理。若需要独立 TTS 也使用解说词库，才进一步验证可选的解说插件桥接。现有词库保持不变，作为未接入或调用失败时的回退来源。是否提供该模式、默认值如何，留待调研验证完成后决定。

## 核对环境与证据

- 手机 2410DPN6CC，Android 16；当前启用 `com.nirenr.talkman/.TalkManAccessibilityService`，解说版本 20261008（236）；豆包输入法 1.5.5。
- 从当前手机只读取得已安装 APK，检查清单和与字符解释有关的两个类。APK、分析工具输出及反编译内容仅保存在忽略的 `docs/local/reader-dictionary-research/`，不进入提交。
- 没有读取用户自定义词库文件，没有复制解说词库或实现到模块，没有安装插件、发送控制广播或改变读屏设置。
- 公开资料：解说官方网站 <https://jieshuo.ltd/>；作者维护的资源及说明仓库 <https://github.com/nirenr/jieshuo>。该仓库不能当作完整服务源码或跨应用接口规范。

## 解说：两条不同路径

### 1. 交给解说自己解释并朗读

当前安装版本的输入法文字处理逻辑，对单个字母或汉字有专门分支：受输入法朗读、密码保护、解释开关等配置影响，调用内部文本处理器后朗读。处理器会使用内置解释表，并在加载时叠加用户的字母/字符资源配置。

这意味着单字交由解说解释有实现依据，但不是所有播报文本都会自动解释。模块目前通过无来源的 HOVER_ENTER 事件传递朗读内容，候选还可能已经附带模块解释。能否仅传原字就得到预期解释，仍需在当前事件路径上实际验证；不能仅凭发现内部方法宣称成功。

需要分别验证：单字候选、多字候选、读屏解释开关、模块解释开关、快速滑动取消、密码框。多字候选不能假定会自动逐字解释。也应检查是否出现双重解释和重复朗读。

### 2. 返回解释文本给模块

当前版本服务公开 Java 方法 `getTextFormatter()` 返回内部处理器，处理器当前混淆名为 `w5.g0`；单字解释分支调用 `p(String)`。该方法先查当前解释表，再回退到语言字符描述并处理字符名称。它返回的可能是包含原字和标点的完整朗读文本，不能假定是纯词条。

这些是同一进程中的 Java 方法，不等于外部应用可调用的 Binder 接口。豆包进程也不能通过普通反射取得另一个进程中的活动服务对象。解说插件若能取得活动 `service` 对象，理论上可以代为调用并返回结果；本次仅确认静态线索，未验证 Lua 可见性、返回文本和生命周期。

风险：`p` 是混淆方法名，升级可能变化；公开方法不代表作者承诺的稳定插件 API；词表异步加载未完成时可能仅返回原字。不能直接把这个调用作为默认生产实现。

当前 APK 清单中的文件、遥测及初始化 Provider 均未导出。无障碍服务受 `BIND_ACCESSIBILITY_SERVICE` 权限保护。动态接收器中可见朗读文本、运行插件、输入法区域等动作，但未在本次核查范围内发现有明确请求/响应协议的字符解释查询动作。TTS_SERVICE 仅能证明提供语音合成，不能证明提供解释词查询。此结论不排除作者另有未公开接口。

## TalkBack 与天坦

TalkBack 官方源码 `ProcessorPhoneticLetters` 内有字符描述映射和 `getPhoneticText` 等方法，但它们属于服务内部对象。本次未发现可供普通输入法直接查询解释文本的公开 IPC。键盘解释路径会检查事件来源窗口是否为输入法窗口；因此不能假定模块当前无来源事件在 TalkBack 下也会触发原生解释。

来源：<https://github.com/google/talkback/blob/master/talkback/src/main/java/com/google/android/accessibility/talkback/eventprocessor/ProcessorPhoneticLetters.java>。本次查看的是 master，未来可能变化。

现有天坦输入法接口本地调研记录包含朗读、触摸探索和区域控制，尚不足以证明存在词条查询接口。让天坦朗读传入字符串，不等于取得它的解释词库。没有向天坦发送猜测的 Binder 事务，也没有绕过授权。

Android `AccessibilityManager` 的公开接口包含服务状态与事件投递等能力，未提供通用字符解释查询：<https://developer.android.com/reference/android/view/accessibility/AccessibilityManager>。

## 后续最小验证方案

1. 用固定公开测试字验证解说的原生解释事件路径，不读取用户输入。对比解说解释开关打开/关闭时结果；不动默认词库。
2. 若需要返回文本，在用户主动运行的独立测试插件里验证 `getTextFormatter()` 和当前单字解释方法。记录加载完成前后、未收录字及自定义解释是否生效，不导出整份词库。
3. 插件验证通过后，再设计可选桥接：校验调用方身份、限制单次字符数、异步处理、超时回退、检测解说版本变化；不得在输入法主线程同步等待，不缓存或导出整份读屏词库。
4. 解说插件不可用、当前读屏改变或方法失效时，继续用模块现有解释。独立 TTS 不能靠“把原字交给解说朗读”取得解释文本。

本次没有修改 Kotlin 或词库，未编译和安装新版本；以上为静态分析和公开资料核查结果，原生解释及插件桥接均未完成运行验收。
